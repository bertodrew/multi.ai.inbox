Inside the web-inbox

  1. Sign in once. The Mailbox login opens the webmail session — same credentials as the Mail UI on /home.
  2. One client, every brand. Mail, folders, compose, calendar, contacts and tasks in one place; each brand’s domain is its own identity.
  3. Pick the right sender. Outbound mail leaves with the brand’s own domain and signature, so SPF, DKIM and DMARC stay clean per brand.
  4. AI triage. Agents file, flag and draft replies over MCP — inference stays on sovereign EU/CH providers.
  5. Search and archive. Full-text search across brands, with retention you control.

Set it up agent-native

  1. Connect a domain. The connector verifies the DNS records — MX, SPF, DKIM, DMARC — before anything ships.
  2. Mint a read-write key. Settings issues a per-tenant key; it is stored server-side only, never in the repository or logs.
  3. One command. Point your agent at the MCP gateway — the exact endpoint and config snippet are in the docs.
  4. Work the mail. Tools list_domains, get_domain_settings, set_domain_settings: agents read and update settings; mail itself flows over IMAP/SMTP.
  5. Everything audited. Connections, zone mutations and key grants land in the audit log.
