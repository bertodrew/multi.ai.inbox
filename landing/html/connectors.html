Use dedicated MCP

Connect Claude or Hermes to this fork’s native MCP server to read and change mail domain settings without opening the Mail UI.

/landingpage/api/mcp
  • list_domains— list all mail domains with quota, aliases and active state
  • get_domain_settings— full settings of one domain (quota, DKIM, relay…)
  • set_domain_settings— change only the attributes you pass, e.g. {"active":"1"}
Claude Desktop / Claude Code config 

            
          


          

            Hermes config example
            

              Add the server to ~/.hermes/config.yaml under mcp_servers,
              with the read-write key from the platform config, then restart Hermes so the
              tools are discovered. Point url at this instance:
            

            
mcp_servers:
  multi-ai-inbox:
    url: "https://<instance-host>/landingpage/api/mcp"
    headers:
      Authorization: "Bearer <read-write API key>"

            
            

              Or from the CLI: hermes mcp add multi-ai-inbox --url https://<instance-host>/landingpage/api/mcp --auth header.
              The tools register as mcp_multi_ai_inbox_list_domains,
              mcp_multi_ai_inbox_get_domain_settings and
              mcp_multi_ai_inbox_set_domain_settings; prompts like
              “list domains and show the settings of example.com” call
              list_domains and get_domain_settings; changes go
              through set_domain_settings.
            

          


          

            The mail API must be enabled in the Mail UI (System → Configuration → Access → API)
            with the docker subnet allowed in API_ALLOW_FROM. The read-write key is read from
            the platform config at runtime — it is never written to this page or the repository.
