Create your first mailbox

Guide 1 · Setup wizard

A mailbox lives on a mail domain of yours. The Setup wizard walks the whole path — origin, DNS, done — in three screens; the mailbox itself is created from the Mailboxes page.

  1. Step 1Origin — open the Setup wizard and confirm the mail origin: the mail UI on this host, reached with your admin credentials.
  2. Step 2DNS — connect Namecheap with your API key (validated and stored server-side only) so the wizard can read DNS records for your domains. Skippable — you can connect later.
  3. Step 3First domain — pick the domain to inspect; MX on the apex, an SPF TXT and a DKIM selector are what inbox placement reads first.
  4. Step 4Done — create the mailbox from Mailboxes: pick the domain, add the address, and the welcome mail goes out.

Records not green yet? Follow Guide 2 — Connect a domain.

Connect a domain

Guide 2 · Namecheap DNS

A mail domain can send and receive once five records exist at your DNS provider (Namecheap). Add the domain in the mail UI first, then publish the records below.

  1. Step 1Add the domain — add it from the mail UI (it cannot be renamed from these pages), then open Settings → DNS snippets to see the records as the registrar serves them.
  2. Step 2A record — at Namecheap → Advanced DNS, create host mail pointing to the IPv4 of your host.
  3. Step 3MX — on the apex (@), point to mail.yourdomain.com with priority 10.
  4. Step 4SPF — a single TXT on the apex: v=spf1 mx ~all.
  5. Step 5DKIM — a TXT at <selector>._domainkey; the key is generated per domain — copy the exact selector and key from the mail UI.
  6. Step 6DMARC — a TXT at _dmarc: start with v=DMARC1; p=none; rua=mailto:postmaster@yourdomain.com and tighten the policy after monitoring.
  7. Step 7Verify — back on Settings → DNS snippets (or Connectors → Browse domains), refresh and confirm each record resolves. Propagation takes minutes to hours.

Use the webmail

Guide 3 · Groupware client

The groupware client ships with the platform — mail, folders, compose, calendar, contacts and tasks in one interface. Sign-in is your mailbox address + password, the same authentication as the mail UI.

  1. Step 1Sign in — open Webmail and click “Open the webmail client”; the client opens in its own tab, then sign in with your mailbox address + password.
  2. Step 2Mail — read conversations in the Inbox and organise them into folders from the folder tree on the left.
  3. Step 3Compose — write, attach files and send; drafts are kept automatically.
  4. Step 4Calendar — create events and invitations in the same session.
  5. Step 5Contacts — add addresses to your address book; they autocomplete while composing.
  6. Step 6Tasks — keep per-mailbox to-dos with due dates.

Switch modules inside the client’s own navigation: Mail · Calendar · Contacts · Tasks.

Automate with agents

Guide 4 · MCP

Connect Claude or Hermes to the platform’s MCP endpoint and let them read and change mail domain settings without opening the panel.

/landingpage/api/mcp
  • list_domains— list all mail domains with quota, aliases and active state
  • get_domain_settings— full settings of one domain (quota, DKIM, relay…)
  • set_domain_settings— change only the attributes you pass, e.g. {"active":"1"}
Connect a client

Point the MCP client at the endpoint above with the header Authorization: Bearer <platform API key> — the read-write key from the platform config. Then prompts like “list domains and show the settings of example.com” call list_domains and get_domain_settings; changes go through set_domain_settings.

The mail API must be enabled (System → Configuration → Access → API) with the docker subnet allowed in API_ALLOW_FROM. The key is read from the platform config at runtime — it is never written to this page or the repository. The full connector surface lives on Connectors.

Manage tenants

Guide 5 · Per-domain administration

Multi-brand operation means one tenant per domain: configuration on Settings, the operator view on Admin — everything scoped to the selected domain.

  1. Step 1Pick the scope — choose the tenant’s domain from the selector at the top of Settings or Admin; everything below follows that scope.
  2. Step 2Tune the domain — on Settings, set branding (description), PTR target and the default/max quota in MiB. The FQDN cannot be renamed here; add or remove domains from the mail UI.
  3. Step 3Watch the domain — on Admin, follow the DNS records in scope, the recent audit trail (connector changes, MCP writes, mailbox operations) and the session details.
  4. Step 4Delegate — access keys for agents and integrations are scoped per domain; creation and revocation ship with the API gateway. Use them with the MCP endpoint from Guide 4.

Operators see only their brand’s domains — the domain-admin view is the same page, narrowed by scope.
