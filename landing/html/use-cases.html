Use cases

One platform, nine jobs: sovereign mail hosting for a multi-brand venture, and the agent layer that runs it — from tenant signup to DNS automation.

Founder / owner Brand operator AI agent End user Customer (tenant)

Multi-brand mail hosting

Customer (tenant) · Founder

  • Self-service signup: a new tenant goes from domain to active mailboxes without touching the admin UI.
  • Per-tenant billing: flat plans, metering of active mailboxes, automated dunning.
  • Branding per tenant: each brand gets its own identity on shared infrastructure.

Agent inbox platform

AI agent · Founder

  • Triage at scale: agents sort, label and escalate mail across every brand inbox.
  • Drafts, not decisions: agents prepare replies; humans approve before anything leaves.
  • Sovereign inference: OpenAI-compatible API keys, default Phoeniqs MaaS (Switzerland) — no US CLOUD Act exposure.

MCP gateway for DNS automation

AI agent

  • Read and write zones: agents list domains and manage MX, A, TXT, CNAME records over MCP.
  • Diff preview + undo: every mutation shows its diff first and can be reverted.
  • Scoped keys: per-domain, per-permission, expiring — never the super-admin key.

Domain management

Founder · Brand operator

  • Registrar connection: connect an account once, see every domain with expiry and lock state.
  • DNS readiness: MX, SPF, DKIM and DMARC verified green/red before launch.
  • Per-domain settings: FQDN, PTR target, quotas and DNS snippets in one page.

Brand operator console

Brand operator

  • Domain-scoped view: operators see only their brand's domains, mailboxes and audit trail.
  • Provisioning: create and remove mailboxes via API or MCP — no shared admin login.
  • Honest states: empty, loading and error states never fake success.

End-user mailboxes

End user · Customer (tenant)

  • Webmail: every inbox reachable on the brand's own domain, with welcome mail on creation.
  • Self-service reset: password recovery without a support ticket.
  • Status at a glance: mailbox list per domain with state and actions.

Sovereign EU/CH infrastructure

Customer (tenant) · Founder

  • Data residency: mail, databases and backups on EU/CH soil only.
  • Screened vendors: hosting and LLM providers chosen so the US CLOUD Act never reaches the data.
  • Swiss alternatives: Infomaniak as the registrar/hosting escape hatch.

Security by default

Founder (CISO)

  • Session rotation: identities re-issued on every successful connect.
  • Credentials at rest: AES-256-GCM, server-side only, never exposed to the browser.
  • Fail-closed endpoints: missing auth is a hard 401/403, rate limits per key and per IP.

Compliance & trust

Customer (tenant) · Legal

  • GDPR transparency: Art. 13/14 notice, cookie table, retention schedule — published, not promised.
  • DPA per tenant: Art. 28 processing agreement ready before the first invoice.
  • 99.5% SLA: measured monthly, with service credits — honest for a single-host era.

How a tenant goes live

  1. Signup — email verified, tenant created, first domain claimed.
  2. DNS readiness — MX, SPF, DKIM, DMARC checked green on the domain page.
  3. Mailboxes — provisioned via API or MCP, welcome mail sent.
  4. Operators — scoped console access; the agent gets a per-domain key.
  5. Billing — metered monthly, flat plan, EU/CH payment rails.

Every step is auditable: connections, zone mutations and key grants land in the audit log.
