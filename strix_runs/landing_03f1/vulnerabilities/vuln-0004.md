# Unauthenticated status.php leaks CSRF token, mailcow origin, public IP, and last connector's username

**ID:** vuln-0004
**Severity:** MEDIUM
**Found:** 2026-10-18 21:46:34 UTC
**Target:** http://host.docker.internal:8080
**Endpoint:** /api/status.php
**Method:** GET
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

An unauthenticated GET /api/status.php leaks the session CSRF token, mailcow origin, server public egress IP, and the last connector's Namecheap username to any anonymous visitor.

## Evidence

Dynamic responses from the live target:

```http
GET /api/status.php HTTP/1.1
Host: host.docker.internal:8080

HTTP/1.1 200 OK
Set-Cookie: MULTIAI_LANDING=e8e381d1fdc68b2764d87560f525ec58; path=/; HttpOnly; SameSite=Lax

{"ok": true, "connected": false, "username": null, "sandbox": false, "csrf": "4af774d5e8a3124c70dd41576f8f7e9e", "mailcow_origin": "https://host.docker.internal", "public_ip": "146.70.126.61"}
```

With a fixed cookie (Cookie: MULTIAI_LANDING=9cdc672410784680891ec7a3d76d84d4), the same unauthenticated response returned CSRF token f0dc2a006b4f97bfc9cded8dc533d0b8 for the attacker-chosen session. No auth gate or CSRF check exists on this route.

## Impact

Any anonymous visitor learns the server's public egress IP (the value a Namecheap operator needs to whitelist), the mailcow origin, and — when a connection exists — the last connector's Namecheap username and sandbox flag, materially aiding the credential-abuse and account-proxying attack chains against this deployment.

## Counterevidence

Actively checked: (1) whether require_csrf or any auth gate covers status.php — it is a GET-only handler that never calls require_csrf or require_namecheap_session; (2) whether Cache-Control no-store or httponly mitigate — no-store affects caching only and does not hide the response; (3) whether the leaked IP is intended client-side data — it is the server's public egress IP fetched from api.ipify.org and exposed to any anonymous visitor. Residual limitation: the username field was null in this run because no successful Namecheap connection existed in the shared store during the test window.

## Confidence Rationale

Working PoC against the live target: unauthenticated request returned HTTP 200 with the session CSRF token, mailcow origin, and public IP in the response body, and the endpoint reads the last connector's username and sandbox flag from the shared global creds store whenever a connection exists (php/status.php:61-72).

## What Would Change This Severity

If the target were confirmed to serve only an internal audience (no anonymous internet visitors), the leaked username/IP would no longer materially aid the attack chains and this would drop to informational.

## Technical Analysis

php/status.php is a GET-only handler that never calls require_csrf() or require_namecheap_session(). It reads $_SESSION['nc_connected'] and the global credentials file (defined as one global path shared by every session in bootstrap.php:16-17), reports the last connector's username and the sandbox flag in the same unauthenticated response, and mints a fresh session CSRF token via ensure_csrf() plus the server's public egress IP via detect_public_ip() (fetched from api.ipify.org and cached under CRED_DIR). The session cookie is HttpOnly and SameSite=Lax, which does not prevent an anonymous visitor from receiving the CSRF token, mailcow origin, public IP, and last-connector username. This is a live oracle for the session-fixation finding (vuln-0002) and the cross-user credential overwrite (vuln-0003): the leaked IP is the exact client_ip value connect.php auto-detects for Namecheap whitelisting, and the last-connector username confirms a fixed session is attached to the previous connector's account.

## Proof of Concept

1. GET /api/status.php with no cookies at all.
2. Confirm HTTP 200 and that the response body includes csrf, mailcow_origin, and public_ip, and reports connected/username/sandbox for the last connector when a connection exists.
3. Repeat with a fixed cookie value to confirm the response reports a CSRF token minted for an attacker-chosen session ID.

```bash
# (a) no cookie, unauthenticated visitor
curl -s http://host.docker.internal:8080/api/status.php
# -> 200, body includes csrf, mailcow_origin, public_ip

# (b) fixed cookie, attacker-chosen session ID
curl -s -H 'Cookie: MULTIAI_LANDING=9cdc672410784680891ec7a3d76d84d4' \
  http://host.docker.internal:8080/api/status.php
# -> 200, body includes csrf token for the attacker-chosen session
```

## Remediation

Gate the connection-state fields behind require_namecheap_session() so connected, username, and sandbox are only reported to connected sessions, and remove detect_public_ip() and the session CSRF token from the unauthenticated response (the CSRF token should only be minted for sessions that actually need it for a state-changing request). Keep Cache-Control: no-store so the gated response is never cached.

## Assumptions

Assumes an anonymous visitor can reach the app and that a Namecheap connection exists in the same shared runtime; the unauthenticated disclosure itself requires no credentials, no user interaction, and no attack preconditions.
